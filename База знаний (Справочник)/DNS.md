# DNS (Domain Name System)

## 📌 Суть (TL;DR)

> **DNS** — это «телефонная книга» интернета. Протокол, который переводит понятные человеку доменные имена (например, `google.com`) в машиночитаемые IP-адреса (например, `142.250.190.46`), чтобы компьютеры могли найти друг друга в сети.

## ⚙️ Механика работы / Архитектура

- **Порты:** Работает в основном по **UDP/53** (для быстрых запросов). Если ответ не влезает в 512 байт или происходит передача зоны (Zone Transfer), используется **TCP/53**.
- **Иерархия серверов:**
  1. **Root (Корневые):** Знают, где искать зоны `.com`, `.ru`, `.net`.
  2. **TLD (Top-Level Domain):** Знают, кто отвечает за конкретный домен (например, `google.com`).
  3. **Authoritative (Авторитативные):** Хранят финальный ответ (точный IP-адрес сервера).
- **Типы DNS-записей:**
  - `A` — связывает домен с IPv4-адресом.
  - `AAAA` — связывает домен с IPv6-адресом.
  - `MX` — указывает на почтовый сервер (Mail Exchange).
  - `TXT` — текстовая запись (часто используется для проверки владения доменом и защиты почты SPF/DKIM).
  - `CNAME` — алиас (псевдоним), перенаправляет один домен на другой.

## 🛡️ Фокус ИБ (Атаки / Логи / Защита)

**⚔️ Векторы атак:**
1. **DNS Spoofing (Cache Poisoning):** Злоумышленник «отравляет» кэш DNS-сервера, подменяя IP-адрес легитимного сайта на IP-адрес фишингового сервера.
2. **DNS Amplification (DDoS):** Атакующий отправляет маленький запрос от имени жертвы (подменив исходный IP), а уязвимый DNS-сервер отправляет жертве огромный ответ (амплификация), забивая ей канал.
3. **DNS Tunneling (Эксфильтрация):** Хакеры упаковывают украденные данные или команды C2 (Command & Control) прямо в DNS-запросы (в длинные текстовые TXT-записи или случайные поддомены). Фаерволы обычно пропускают DNS-трафик, чем и пользуются атакующие.
4. **DGA (Domain Generation Algorithm):** Малварь генерирует сотни случайных доменных имен в день (например, `x8f9q2p.com`) для связи с сервером управления, чтобы аналитики не могли заблокировать один статический домен.

**🔎 Мониторинг и Логи:**

- В SIEM отслеживаются всплески DNS-запросов к неизвестным или подозрительно длинным доменам.
- **Sysmon Event ID 22** — логирует все DNS-запросы на Windows-хосте (показывает, какой процесс запросил домен).
- Анализ `NXDOMAIN` (ответ "домен не найден") — если их слишком много, возможно, в сети работает малварь с DGA.

**🛡️ Защита:**

- **DNSSEC:** Добавляет криптографические подписи к DNS-записям, защищая от подмены (Spoofing).
- **DoH / DoT (DNS over HTTPS / TLS):** Шифрует DNS-трафик, чтобы провайдер или MITM-атакующий не видели, какие сайты посещает пользователь.
- **DNS Sinkhole:** Перенаправление вредоносных доменов на внутренний безопасный IP-адрес («черную дыру»), чтобы разорвать связь малвари с хакером.
